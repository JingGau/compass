# 查询规划

**职责**：根据实体、场景，制定具体的查询方案，展示给用户确认后执行。

> 本文件被 SKILL.md Step 4 引用，核心约束以 SKILL.md 为准，本文件负责具体执行细节。

---

## ⛔ 执行前硬约束

0. **必须遵守 `tools/tool_protocol.md`**：每轮先读状态与注入上下文，查询后跑传感器，推进前做断言门禁
1. **用户明确确认方案之前，禁止调用任何 adapter**
2. **单线顺序执行**，禁止并行方案、禁止父子 Agent
3. **内部 Adapter 优先**：通过 `adapters/<n>/client.py` 调用；JDBC / 外部库须用户确认后才能使用
4. **空结果最多重试 3 次**，仍无结果停下来告知用户
5. **环境探查（Step 0）不得跳过**：未读各 adapter `config.yaml` 前，不得假设工具可用
6. **prod 环境 SQL 强卡 EXPLAIN**：按 `guards/sql-safety.md` 三档流程执行，任何模式（含自动模式）不可绕过；🟢 自动继续，🟡 等待确认，🔴 必须明确确认
7. **每步必须按顺序输出三块**：Before Block → Safety Gate Block → 执行 → After Block；任何一块缺失视为未完成，禁止继续下一步
8. **每步必须先生成 Action Card**：用 `tools/action_cards.py` 表达本次动作；禁止直接调用 adapter、直接读代码、直接查日志后再补说明
9. **所有 After Block 必须产出线索**：traceId/接口/方法/表/key/时间戳至少逐项说明「发现」或「未发现，已尝试什么」

## 执行模式

| 模式 | 触发 | 行为 |
|------|------|------|
| 自动模式 | 用户选 0 / 历史策略编号 | 方案确认后全自动跑完，每步输出 Before Block → Safety Gate Block → After Block，不中途停下来（🟡/🔴 风险和外部库除外） |
| 手动模式 | 用户选 M | 每步执行前停下来，让用户确认工具/轨道；确认后输出 Safety Gate Block，执行，输出 After Block，再停下来 |

> **强制暂停例外**（任何模式下都必须暂停）：
> - prod SQL EXPLAIN 判定为 🟡 中风险或 🔴 高风险
> - 需要使用外部库（JDBC / 非内部 adapter）
> - 空结果重试 3 次仍无结果

## 执行模型

| 用户说 | 行为 |
|--------|------|
| 「好」「可以」「确认」「开始」 | 开始执行 |
| 意图不明确 / 无回复 | 默认走 0 号自动模式 |
| 「等等」「停」「先别查」 | **立即中断，保留已有结果** |

## 📡 执行播报格式（Before / After Block）

> **每一步查询，无论自动模式还是手动模式，都必须先输出 Before Block 再执行，执行完立即输出 After Block。这是强制格式，不可省略。**
> Before/After 必须由 `InvestigationAction` 和 `ActionResult` 渲染，不允许自由发挥成散文。

### Before Block（执行前播报）

```
▶ Step N — [步骤名]
- 目的：___（这一步要澄清什么问题）
- 工具：___ [内部/外部] · 环境/Profile：___
- 查询对象：___（关键字 / 表名+字段 / Redis key 模式 / SLS 查询语句摘要）
- 预期：看到 ___ 才算有价值；若为空则 ___
```

不同轨道必须展开到可复核粒度：

| 轨道 | Before 必须展示 |
|------|------------------|
| SLS | 完整搜索语句、时间范围、limit、容器/服务名 |
| SQL | 完整 SQL；prod 还必须展示完整 EXPLAIN SQL |
| 代码 | 应用名、文件/类/方法名、来源线索；B 端必须展示页面→API→后端入口的定位路径 |
| Redis | 命令、key 模式、profile、范围限制 |
| ES | index、query body、size/from/agg 限制 |

### After Block（执行后播报）

```
✅ Step N 完成 · 耗时 ___
- 结果摘要：命中 ___ 条 / 返回 ___ 行 / 状态：___
- 关键发现：___（直接影响下一步判断的核心内容，不得写「无」）
- 提取线索 →
    · 类名/接口名：___（无则写「未发现」）
    · traceId/tlogId：___（无则写「未发现」）
    · 表名/key 模式：___（无则写「未发现」）
    · 异常时间戳：___（无则写「未发现」）
- 下一步：→ ___（明确说下一步去哪个轨道 / 做什么）
```

> **「提取线索」是核心字段，不允许整行留空或写「无」。** 若某项真的未发现，必须写「未发现，已尝试：___」并说明原因。线索会被带入下一轨，是三轨不跑偏的唯一保障。
> After Block 必须列出「可继续下钻」候选：可查代码、可查 SQL、可拉链路、可查日志、可查缓存中至少选出适用项。

## 🔒 Safety Gate Block（安全门控输出，强制）

> **每次调用 adapter 前，Before Block 之后、实际执行之前，必须输出 Safety Gate Block。**
> 这不是可选的过程描述——它是让用户看见安全检查被执行的唯一证明。缺失视为安全门控未执行。

完整执行顺序：
```
▶ Before Block
🔒 Safety Gate Block   ← 此处强制输出，展示检查过程和结果
（执行查询）
✅ After Block
```

---

### SQL Safety Gate（prod 环境，每条 SQL 必须执行）

```
🔒 Safety Gate — SQL
├ 白名单检查：✅ SELECT（允许）/ ❌ [关键字]（已拒绝，不执行）
├ 环境：prod → 强制 EXPLAIN ｜ test/uat → 跳过 EXPLAIN，直接执行
├ 执行 EXPLAIN：
│     [在此粘贴完整 EXPLAIN SQL]
│     结果：type=___, rows≈___, key=___
└ 判定：🟢 低风险，自动继续 / 🟡 中风险，见下方警告 / 🔴 高风险，见下方警告
```

> **EXPLAIN SQL 必须原文展示，不得省略或用「已执行」代替。**
> **EXPLAIN 结果关键字段（type / rows / key）必须逐项列出。**

🟢 低风险后直接跟执行，无需用户操作：
```
🔒 Safety Gate — SQL
├ 白名单检查：✅ SELECT
├ 环境：prod → EXPLAIN
├ 执行 EXPLAIN：
│     EXPLAIN SELECT available_amount FROM t_user_wallet WHERE user_id = 123456
│     结果：type=range, rows≈1,200, key=idx_user_id
└ 判定：🟢 低风险，自动继续
```

🟡/🔴 风险后输出警告卡片，格式见 `guards/sql-safety.md`，在此暂停等待用户操作。

🟡/🔴 风险必须同时写入 `pending_confirmations`：

```
pending_confirmation:
  action_id: Step N
  gate_type: sql
  risk_level: medium/high
  required_reply: 确认执行
```

> 没有 pending_confirmation 记录，视为门禁未完成，禁止继续执行。

---

### SLS Safety Gate（每次 SLS 查询必须执行）

```
🔒 Safety Gate — SLS
├ 时间范围：___ h（上限 168h）→ ✅ 合规 / ❌ 超限，已自动收窄至 168h
├ 条数限制：limit=___（上限 500）→ ✅ 合规 / ❌ 超限，已自动设为 500
├ 上下文保护（按 context-limits.yaml）：
│     预估命中：___ 条
│     若 ≤ 50 条 → 全量载入上下文
│     若 > 50 条 → 概览统计 + 智能采样 15 条载入上下文
│                   完整结果写入：/tmp/investigation/sls_[traceId/keyword]_[timestamp].log
└ 字段裁剪：保留 __time__ / level / message / traceId / exception / request_uri / status
            丢弃 __source__ / host / pod / namespace 等基础设施字段
```

After Block 的「结果摘要」字段在 SLS 查询后必须补充采样说明：
```
✅ Step N 完成 · 耗时 ___
- 结果摘要：命中 128 条（全量）→ 载入上下文 15 条（智能采样）
    · 采样策略：首条 + 末条 + 所有 ERROR(8条) + 状态变化点(4条)
    · 完整结果：/tmp/investigation/sls_abc123_20260405143200.log（可用「看更多」下钻）
- 关键发现：...
```

> **命中条数（全量）和载入条数必须分开标注，不得只写「查到了日志」。**

---

### Redis Safety Gate（每次 Redis 查询必须执行）

```
🔒 Safety Gate — Redis
├ 命令白名单检查：[命令名] → ✅ 允许 / ❌ 禁止（KEYS/FLUSHALL/SET/DEL 等，已拒绝）
├ 参数检查：
│     SCAN count: ___ （上限 100）
│     LRANGE/ZRANGE 范围: ___ 条（上限 100）
│     HGETALL 字段数预估: ___ （超 500 需警告）
├ 环境：___ profile
└ 库风险级别：普通库 → 直接执行 / 高危库（finance-prod 等）→ 见下方确认
```

高危库确认格式（执行前强制暂停）：
```
⚠️ 高危库操作确认
┌──────────────────────────────────────┐
│ 目标库：finance-prod                  │
│ 命令：GET wallet:123456               │
│ 风险：直接访问生产资金数据             │
└──────────────────────────────────────┘

**[确认查询]** **[换 test 环境]** **[跳过此步]**
```

> **高危库的定义由用户在 `guards/redis-safety.md` 中配置。未配置该文件时，所有 prod Redis 操作均视为高危，强制确认。**

---

### ES Safety Gate（每次 ES 查询必须执行）

```
🔒 Safety Gate — ES
├ 操作白名单：___ → ✅ _search（允许）/ ❌ _delete/_bulk 等（已拒绝）
├ 参数检查：
│     size: ___（上限 100）
│     from + size: ___（上限 10000，防深分页）
│     agg terms size: ___（上限 1000）
└ 判定：✅ 合规，继续 / ❌ 超限，已自动调整为上限值
```

---

### 外部库 Safety Gate（platform / JDBC 等）

```
🔒 Safety Gate — 外部库
├ 库类型：platform（Doris JDBC）
├ 内部 adapter 覆盖检查：❌ 内部 adapter 不覆盖该数据源
└ 需用户确认后方可调用

⚠️ 外部库调用确认
┌──────────────────────────────────────────┐
│ 库：platform（Doris JDBC）               │
│ Catalog：hive_catalog.ods_order_cdc      │
│ 原因：内部 mysql adapter 不覆盖分析宽表   │
└──────────────────────────────────────────┘

**[确认使用]** **[换内部方案]** **[跳过此步]**
```

---

### Safety Gate 禁止行为

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| Safety Gate Block 整体省略 | 每次 adapter 调用前必须输出对应 Gate |
| EXPLAIN 只写「已执行」不贴 SQL 和结果 | 必须原文展示 EXPLAIN SQL + type/rows/key |
| SLS 只写「查到日志」不写条数 | 必须写全量命中条数 + 载入条数 + 采样策略 |
| 高危库未输出确认卡片直接查 | 高危库必须暂停输出确认卡片等用户操作 |
| Redis 禁止命令静默跳过 | 禁止命令必须明确输出「已拒绝，原因：___」 |
| 上下文超限不写临时文件路径 | 超限时必须输出临时文件路径，供用户下钻 |

## 规划步骤

### ▶ Step 0：环境探查（必做，不可跳过）

1. 读取每个 adapter 的 `config.yaml`，确认 `enabled`、profiles、连接信息，并标注内部/外部类型
2. Platform adapter 额外探查：执行 `SHOW CATALOGS`，JDBC catalog 用三段式路径访问
3. 输出可用工具清单，**外部库明确标注**：

```
当前可用工具：
  sls            → prod, test, uat           [内部]
  mysql          → polardb-test, polardb-uat, main-test, main-uat  [内部]
  redis          → finance-test/uat, activity-test/uat, price-test/uat, redis2-test  [内部]
  elasticsearch  → test-finance（6.x）       [内部]
  platform       → prod（Doris JDBC）        [外部 ⚠️ 需用户确认]
```

4. 环境隔离原则：不同环境数据不能混查；每步必须标注环境/profile

✅ **Step 0 完成，继续 Step 1。**

---

### ▶ Step 1：匹配历史策略

读取 `memory/strategies.yaml`，按多维度评分排序，展示 Top 3 + 0号自动模式 + M号手动模式。

✅ **Step 1 完成，展示方案后停止等待用户确认。**

---

### ▶ Step 2：三轨入轨声明（0号自动模式必做）

> 开始执行前，AI 必须先声明入轨方式，用户可以在此纠正方向，避免查了一半才发现跑偏。

**根据当前掌握的信息，从三种入轨方式中选一种：**

| 入轨方式 | 触发条件 | 第一步做什么 |
|---------|---------|------------|
| 🔵 代码先行 | 已知接口名 / 业务场景明确 / 有服务名 | 读接口代码 → 提取关键字/表名 → 带着发现查日志或DB |
| 🟡 日志先行 | 不知道接口，但有关键字（用户ID/订单号/交易号） | 宽关键字查日志 → 找到接口名/traceId → 读该接口代码 → 继续深查 |
| 🟢 数据先行 | 有明确异常数据表现，知道哪张表或哪个字段 | 关键字找相关表 → 看哪些接口写这张表 → 读代码分析逻辑 |

**声明格式（必须输出）：**

```
本次选择 [🔵代码先行 / 🟡日志先行 / 🟢数据先行]
原因：___
第一步将：___
```

> 用户可在此纠正入轨方式，确认后再执行。

---

### ▶ Step 3：三轨协作执行（核心）

> 三轨不是串行切换，而是**交织推进**——任何一轨有新发现，立刻带入最相关的另一轨。
> **每一步进入前输出 Before Block，完成后输出 After Block，After Block 的「提取线索」决定下一轨的输入。**

---

#### 🟡 日志轨强制子流程（不可跳步）

> 只要进入日志轨，必须完整走完以下四步，不得在任何一步停下来就报告结果。

---

**日志轨第一步：关键字查日志（宽查）**

输出 Before Block → 执行 → 输出 After Block：

```
✅ 日志轨 Step 1 完成 · 耗时 ___
- 结果摘要：命中 ___ 条
- 关键发现：___
- 提取线索 →
    · traceId/tlogId 字段是否出现：是 / 否
    · 命中的日志关键字：___
    · 初步判断涉及服务：___
- 下一步：→ 立即执行日志轨第二步（提取链路ID），不得在此停留
```

> ⛔ **禁止在第一步完成后输出任何结论或分析，必须立即执行第二步。**

---

**日志轨第二步：提取链路 ID（强制）**

从命中日志中提取 traceId / tlogId / requestId 等链路标识。

- 若单条日志无链路ID → 扩大时间窗 / 换关键字重试，最多 3 次
- 若确实无链路ID → 标注「⚠️ 无链路ID」并记录已尝试内容，继续第三步用时间窗替代

```
✅ 日志轨 Step 2 完成
- 提取线索 →
    · traceId：___ （无则写「未发现，已尝试：扩大时间窗×2、换关键字×1」）
    · tlogId：___
    · requestId：___
- 下一步：→ 立即执行日志轨第三步（拉全链路），有链路ID时此步强制执行
```

> ⛔ **有链路ID时，禁止跳过第三步直接分析。无链路ID时，必须在此处明确标注后才能继续。**

---

**日志轨第三步：拉全链路日志（强制）**

用 traceId / tlogId 拉该请求的完整调用链，重点关注 ERROR/WARN 条目、超时节点、异常堆栈首次出现位置。

```
✅ 日志轨 Step 3 完成 · 耗时 ___
- 结果摘要：全链路共 ___ 条日志，涉及服务 ___ 个
- 关键发现：ERROR 首次出现在 ___，WARN ___ 处，超时节点 ___
- 提取线索 →
    · 类名/方法名：___
    · 接口路径：___
    · 涉及表名：___（从日志关键字推断）
    · Redis key 模式：___
    · 异常堆栈首行：___
    · 首次异常时间戳：___
- 下一步：→ 立即执行日志轨第四步（提取线索触发代码轨）
```

---

**日志轨第四步：提取线索 → 强制触发代码轨**

从全链路日志中整理所有线索，**必须二选一，不得跳过**：

**情况 A：找到类名或接口名**

```
✅ 日志轨 Step 4 完成
- 提取到入口：___ （类名#方法名 或 接口路径）
- 涉及表名：___
- ⛔ 禁止在此停留，立即进入 🔵 代码轨：
    读取 projects/___.md → 定位源码路径 → 读取对应代码
```

**情况 B：未找到任何类名或接口名**

```
✅ 日志轨 Step 4 完成
- ⚠️ 代码轨无法触发
- 已尝试：___（描述换了哪些关键字/时间窗/日志级别）
- 原因判断：___
- 后续结论将标注「⚠️ 弱结论 — 代码轨未覆盖」
- 下一步：→ 进入 🟢 数据轨，用已知表名/时间戳验证数据状态
```

> ⛔ **情况 A 下，禁止在日志轨第四步完成后直接输出最终结论，必须先完成代码轨。**

---

#### 🔵 代码轨执行格式

```
▶ 代码轨 — 读取 [类名#方法名 / 接口路径]
- 来源线索：来自日志轨第四步 / 来自数据轨发现
- 读取目标：projects/___.md → 源码路径 ___
- 预期：提取日志关键字、涉及表名、Redis key 模式、业务逻辑分支

✅ 代码轨完成
- 关键发现：___（业务逻辑中哪个分支与问题相关）
- 提取线索 →
    · 日志关键字：___
    · 写入表名：___
    · Redis key 模式：___
    · 异常分支条件：___
- 下一步：→ 进入 🟢 数据轨，验证上述表名/key 的实际数据状态
```

B 端页面问题必须优先形成页面调用链：

```
页面组件 → 前端 API 常量 → 后端 Controller → Service → Feign/Mapper → 表/缓存
```

每一段必须说明「为什么能连上」：
- 页面组件中哪个方法触发请求
- API 常量对应哪个 URL
- Controller 的 `@RequestMapping` / 方法注解如何匹配 URL
- Service/Mapper 如何决定业务含义和过滤口径

---

#### 🟢 数据轨执行格式

```
▶ 数据轨 — 查询 [表名 / Redis key / ES index]
- 来源线索：来自代码轨 / 来自日志轨
- 工具：___ [内部/外部] · 环境：___
- 查询条件：___
- 预期：___
```

#### ⛔ 三轨收敛门控（进入结果分析前必须通过）

完成各轨查询后，**必须输出以下三轨状态卡，通过门控才能进入 result-analysis.md**：

```
📋 三轨状态卡

| 轨道 | 状态 | 核心发现 | 遗留问题 |
|------|------|---------|---------|
| 🟡 日志轨 | ✅完成 / ⚠️部分 / ❌未触发 | ___ | ___ |
| 🔵 代码轨 | ✅完成 / ⚠️部分 / ❌未触发 | ___ | ___ |
| 🟢 数据轨 | ✅完成 / ⚠️部分 / ❌未触发 | ___ | ___ |

收敛判断：
□ 三轨互相印证 → 给强结论，进入 result-analysis.md
□ 某轨未触发，其余两轨已闭环 → 给弱结论，结论标注「⚠️ ___ 轨未覆盖」
□ 代码轨状态为「未触发」且无情况B说明 → ⛔ 禁止进入结论，必须补充原因
□ 三轨均无线索 → 停下来告知用户，请求补充信息
```

---

#### 三轨禁止行为

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| 执行前不输出 Before Block | 每步必须先输出 Before Block 再调用 adapter |
| 执行后不输出 After Block | 每步完成后立即输出 After Block，提取线索不得留空 |
| 关键字查到日志后直接报告，不提取链路ID | 命中日志 → 立刻找 traceId/tlogId → 拉全链路 |
| 有链路ID但不拉全链路 | 有链路ID就必须拉全链路，这是强制步骤 |
| 全链路日志分析完不读代码，直接给结论 | 日志轨第四步找到类名 → 立刻进代码轨 → 完成后才能收敛 |
| 三轨状态卡未输出就进入结论 | 必须输出状态卡并通过收敛门控 |
| After Block「提取线索」整行写「无」 | 每项未发现时写「未发现，已尝试：___」 |
| 某一轨查不到就埋头继续查同一轨 | 查不到时带着已有线索跳到另一轨 |

## 格式规则

1. 方案头部必须有摘要卡片，含入轨方式和执行模式
2. 入轨声明必须在步骤表格前单独输出
3. 工具列必须标注内部/外部
4. **每步执行前输出 Before Block，执行后输出 After Block，两者缺一不可**
5. **After Block「提取线索」每项不得整行留空，未发现时写「未发现，已尝试：___」**
6. **进度表新增「提取线索」列，体现三轨流转的输入来源**
7. **进入结论前必须输出三轨状态卡并通过收敛门控**
8. 手动模式每步必须有备选方案供用户选择
9. 选项必须用加粗方括号 `**[选项]**`
10. 不要大段纯文本，超过 3 行转表格或列表
