# 结果分析

**职责**：汇总多源查询结果，控制上下文大小，脱敏展示，给出分析和判断。

> 本步骤被 SKILL.md Step 7 引用，结论卡片面向提问者，独立可复制。

---

## 用户角色适配

| 维度 | 技术用户 | 业务用户 |
|------|---------|---------|
| 结论卡片 | 含代码引用、根因分析 | 只说业务结论 + 建议操作 |
| 数据明细 | 展示原始数据表格 | 只展示关键对比（正常值 vs 异常值） |
| 异常分析 | 多源交叉分析 + 代码逻辑 | 一句话说原因 |
| 建议操作 | 技术方案（清缓存、查配置） | 业务方案（让用户重试、联系开发） |

> **业务用户禁止展示**：SQL 查询结果原始表、Redis key/value、代码类名、adapter 名称、SLS 原始日志

---

## 中断感知

| 用户说 | 行为 |
|--------|------|
| 有新消息 | 暂停后续分析，响应用户后继续 |
| 「直接给结论」 | 跳过深度分析，基于已有数据给判断 |
| 「够了」 | 结束排查 |

---

## 部分失败 / 无数据时的分析义务

若某步**无结果、报错或样本过少**：
- 结论卡片中**明确标注**该步状态（⚠️ 未证实 / ❌ 失败），不得假装已闭环
- 给出**下一步建议**：改条件、换工具、或请用户补充信息
- 若用户未确认继续，可给出**在当前证据下的弱结论**，并列出待验证假设

无结果时固定提示：
```
未找到匹配数据，建议：放宽时间范围 / 换查询维度 / 确认 ID 是否正确
```

## 大结果集处理

查询执行后、分析展示前，先检查结果集大小，参考 `guards/context-limits.yaml`。

### Phase 1 — 概览统计（不消耗上下文）

```
SLS 查询结果概览：
  匹配总数: 1,283 条
  时间范围: 14:20:00 - 14:45:00
  级别分布: INFO 1,245 / WARN 23 / ERROR 15
  去重异常类型:
    - InsufficientBalanceException (8次)
    - TimeoutException (5次)
    - NullPointerException (2次)
  高峰区间: 14:30-14:35（占 78%）
```

### Phase 2 — 智能采样（控制上下文大小）

采样策略：
- 第一条日志（问题起点）
- 最后一条日志（当前状态）
- 所有 ERROR 日志（最多取 `context-limits.yaml` 中 `sls.max_error_sample` 条）
- 状态变化点（字段值从 A 变为 B 的记录）
- 异常堆栈首次出现（去重后）

字段裁剪：只保留 `time`、`level`、`message`、`traceId`、`exception`，丢弃 `host`、`container`、`pod`、`namespace`、`__source__` 等冗余字段，预期减少 50-70% 文本量。

### Phase 3 — 临时文件（超大结果集兜底）

超过 `context-limits.yaml` 中 `max_total_rows` 限制时：
1. 完整结果写入 `/tmp/investigation/{session_id}/{adapter}_{timestamp}.jsonl`
2. AI 只读取 Phase 2 采样后的关键日志
3. 告知用户：「完整结果已保存到临时文件（共 X 条），当前展示 Y 条关键日志」
4. 用户可按需下钻（见 Phase 4）
5. 排查结束后清理临时文件

### Phase 4 — 按需下钻

| 用户说 | AI 操作 |
|--------|---------|
| 「看更多日志」/ 「继续」 | 从临时文件加载下一批（默认 10 条） |
| 「看 14:30-14:32 的」 | 按时间范围筛选 |
| 「看所有 ERROR」 | 筛选 level=ERROR |
| 「看第 200-210 条」 | 按行号读取 |
| 「搜索 xxx 关键字」 | 在临时文件中 grep |
| 「导出结果」 | 告知临时文件路径 |

## 展示结构

### 1. 结论卡片（最重要，放最前面）

> 结论卡片必须独立成段，能直接复制发给提问者。

**写作要求：**

| 要求 | 说明 |
|------|------|
| 独立完整 | 不依赖上下文就能理解问题全貌 |
| 问题描述先行 | 先复述用户反馈的问题，再给根因 |
| 根因说人话 | 用业务语言（「缓存过期」而非 `RedisConnectionException`） |
| 影响范围必写 | 是否影响其他用户 |
| 建议可操作 | 具体到「做什么」和「做了之后会怎样」 |
| 语气恳切专业 | 「希望以上信息能帮助解决问题，如有疑问可以随时追问」 |
| AI 声明 | 末尾必须标注免责声明 |

**模板（技术用户）：**

```markdown
> **排查结论**
>
> | 维度 | 内容 |
> |------|------|
> | 问题描述 | 用户反馈余额显示为 0，实际已充值 200 元 |

> 希望以上信息能帮助解决问题，如有疑问可以随时追问。
```

## 格式规则

| 规则 | 说明 |
|------|------|
| 结论最先 | 结论卡片永远放最前面 |
| 结论独立 | 能单独复制发给提问者，不依赖上下文 |
| 数据用表格 | 超过 2 个字段的数据都用表格 |
| 异常高亮 | 异常值跟 ❌ 或 ⚠️，正常值跟 ✅ |
| 大结果集分层 | 概览统计 → 关键采样 → 下钻入口 |
| 操作选项格式 | 加粗方括号 `**[选项]**` |
| 不用大段纯文本 | 超过 3 行转表格或列表 |
| AI 声明必写 | 排查结论和建议操作末尾必须标注 |
| 语气恳切专业 | 有温度但不过度热情 |
